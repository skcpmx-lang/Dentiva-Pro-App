# Relational schema specification

All mutable aggregates carry `id`, created/updated UTC timestamps and actor attribution where relevant. Internal IDs are UUID text. Foreign keys default RESTRICT, never silently cascade clinical or financial history. Cascades are allowed only for owned configuration/join rows inside an explicitly authorized aggregate transaction. Archived entities are filtered by default but remain resolvable historically. Text fields have domain length limits, not ASCII restrictions. Every schema change has transactional SQL, checksum and version in `schema_migrations`.

## Index contract
B-tree indexes: patient code (unique), normalized name + id, phone/contact phone, registration timestamp + id, assigned dentist; appointments starts_at+dentist+status; queue clinic_date+status+priority; invoices number (unique), patient+date, due_date+state; payments received_at+method, patient; allocations invoice_id; visits patient+started_at and dentist+date; prescriptions patient+issued_at; treatment catalog code/name; treatment record catalog+date; inventory SKU (unique), batch expiry, movement item+date; audit timestamp+sequence, actor+timestamp, entity+entity_id; attachments patient_id. Index all child FKs used on restriction and lookups. Search prefixes escape `%`, `_` and `\`; FTS tokenizer accepts Unicode. Sorting uses allowlisted columns.

## Consistency
Amounts integer poisha 0..9,000,000,000,000; checked intermediates; quantities fixed thousandths where fractional quantities are supported. Invoice total equals sum of immutable line totals; payment allocation sum <= payment amount and invoice due. Composite FKs or triggers enforce patient equality across invoice/payment/visit/prescription and item equality across stock batches. Over-allocation is rejected at the persistence boundary as well as domain validation. Financial rows cannot be deleted or edited after posting. Sequence increment, header, details, allocation and audit commit/rollback together.

## Migration / health
Connection bootstrap enforces foreign_keys=ON, journal_mode=WAL, synchronous=FULL, busy_timeout=5000; verifies returned FK state. Migration applies before sessions, under exclusive startup/write gate; hashes prevent editing a deployed migration. Refuse unknown newer schemas; do not downgrade. quick_check on normal startup, full integrity_check + foreign_key_check during backup validation, restore and QA. Never auto-delete/recreate a damaged database. Migration test restores every supported historical schema and checks counts, relations and money.
