# Shared print/PDF rendering specification

Single structured document engine: authorized typed data + immutable template version + printer profile + licensed local fonts -> measured paginated display list -> preview, PDF, Windows print. No independent handwritten print layouts. Renderer never fetches remote fonts/assets or executes user HTML. Escape all free text. All output actions reauthorize source data and documents.print; PDF/export also requires data.export. Profile edits require printers.manage.

## Geometry / engine
Micrometre integer paper/margin measurements, points for font metrics, DPI-aware screen conversion; A4 210×297mm, A5 148×210mm, 58/80mm thermal and custom width/height within validated device limits. Profile includes device identity, document type, dimensions, portrait/landscape, all margins, font scale, copies, header/footer and thermal capabilities. Printer enumeration uses Windows spooler; wireless/Bluetooth support means Windows-exposed printers only, not a proprietary transport promise. Query printable area and minimum hardware margins. Warn and require correction when a profile is physically impossible; do not silently scale unreadable text.

Measure after local fonts and images are loaded. Bengali shaping requires HarfBuzz/compatible shaping and embedded licensed font subset; codepoint support alone is insufficient. Long unbroken strings wrap safely. Repeated table headers; keep medication instruction with its medicine where it fits; split very long rows with continuation labels rather than clipping. Page headers/footers reserve space. Each page is numbered and preview uses exactly that geometry with zoom controls. No screen overflow:hidden on printable content. Thermal documents stack sections vertically; suppress optional decoration but never medication information.

## Prescription
Header: clinic name/logo (contain, no stretch), address/phone; dentist and ALL ordered designations. Patient name/gender/age/date, optional code. A4/A5 columns: left C/C, O/E, R/E, Advice; right medication table name/form/strength/dosage/schedule/meal/duration/instruction including route/PRN notes. Values are clinician input; examples in the master prompt are labels/examples, NOT boilerplate diagnoses. Narrow paper uses a sequential clinical section then medications. Footer clinic message/hours/configured text; signature minimum 28mm unobstructed signing height with rule/caption, keep whole block together, push to new page if needed. No cramped bottom margin signature.

## Invoice / summary / reports
Invoice: clinic header, number/date/patient/code, items with quantity/unit/discount/tax/subtotal/total/paid/due/status, currency ৳. No dentist signature/footer unless explicitly enabled. Thermal totals follow item rows; no enormous fixed whitespace. Patient summary and reports use permission-filtered fields, date range and attribution. Financial tables reconcile exactly with command DTOs; never recalculate monetary amounts in render code.

## PDF / Windows interaction
PDF has actual page MediaBox, embedded font(s), Unicode text mapping, embedded logo and repeatable page breaks. Direct export writes through a native chosen destination using staged atomic replacement and overwrite confirmation. Windows printing selects a profile/device/copies with native dialog; cancellation is not success. Save as PDF via Windows print is available separately. Print preview is not a claim that a physical printer printed. Unavailable printer: identify selected device, re-enumerate, alternative choice, PDF and retry; retain document. Do not store clinical contents in debug logs/spool diagnostics.

## Required evidence
Automated geometry assertions for every page and text box + extracted Unicode/text completeness + golden raster reviews at A4/A5/58/80/custom landscape/portrait. English/Bengali mixed names, combining marks, many medications, long advice/clinic/designation/patient text, many invoice lines, discounts/tax/partial/full/due. Real Windows PDF viewer and spooler tests plus physical standard/network/Bluetooth-exposed printer tests on declared supported hardware. Log driver, paper, DPI, font version, document hash and visual signoff. These gates cannot pass from browser print CSS alone.
