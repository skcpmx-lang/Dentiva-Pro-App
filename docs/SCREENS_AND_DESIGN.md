# Screen, interaction and component specification

## Design system
Central tokens: navy #112D42, teal #087F79, canvas #F3F6F8, surface #FFFFFF, text #182F40, secondary #536776, border #D8E2E7, danger #B42318, warning #8A5800, success #157347. Verify contrast for every pairing, never infer from hue. Radius 6px fields/8px cards, spacing 4/8/12/16/24/32, compact desktop controls >=36px (icon hit area >=40px), subtle 120–180ms transitions, reduced-motion disables motion. Font: locally bundled licensed Latin UI sans + Noto Sans Bengali, complete required shaping weights. Font hierarchy: title 26/32, section 20/28, card 16/24, body/table 14/21, label 13/20, metadata 12/18. Icons are consistent line geometry, with visible names/tooltips. Status always has text/icon as well as color.

Shell: 264px expanded / 80px collapsed sidebar; compact layouts preserve scroll, never overlay the content. Header has branding, clinic, clinic-local date, user, notification center, lock and profile/logout. Sidebar groups and destinations exactly follow master sections 48–49. Main uses min-width:0, constrained scrolling and sticky table headers. Dashboard grids 3+3 / 2+2; one column only when effective width requires it. Test 1280×720 through 2560×1440 and effective viewport at 200% scale. Modal max-height viewport minus 32px, internal scroll, focus trap, accessible label, restored focus and inert background. Escape obeys unsaved confirmation.

## Shared components and states
Button, IconButton, TextField, TextArea, Select, DateRange, MoneyInput, StatusBadge, DataTable, Pagination, Drawer, Dialog, ConfirmDestruction, Toast, NotificationPanel, EmptyState, ErrorState, LoadingState, UploadZone, Timeline, PrintPreview, AppShell. All support applicable default/hover/focus/active/selected/disabled/loading/error/empty/success/warning states. No disabled feature advertised as available; disabled submit represents validation/in-flight operation, not missing implementation. Every read has loading/empty/error/retry; every write prevents duplicates and provides inline actionable failure without closing data. Form submission via keyboard; labels, required indicators, sensible tab order; dirty navigation/save/discard/cancel. Native auto-lock hides sensitive DOM immediately and retains drafts only in protected memory; reauthentication precedes unsaved-data decisions, never postpones the lock.

Shortcuts: Ctrl+K/F2 global search; Ctrl+N context new; Ctrl+S current form; Ctrl+P permitted current document; Escape close permitted overlay. Do not capture browser/native text-editing shortcuts unnecessarily. Visible shortcut help. Dates use shared Asia/Dhaka calendar half-open [start,end) UTC boundaries; Today/Yesterday/7/30/90 days/Last Year/This Month/Previous Month/Custom everywhere. Patients default Today and newest, appointments upcoming, payments/invoices/audit newest; attention-first stock.

## Import/export and destructive decisions
CSV exports neutralize spreadsheet formula prefixes and obey source grants + data.export. CSV patient/catalog imports have preview, strict headers, Unicode validation, row errors and atomic commit, not silent coercion. Optional external formats are not advertised. Hard patient deletion is allowed only when no protected history exists, with counts and typed code; otherwise archive. Business/all-data reset requires owner reauthentication, mandatory backup, exact clinic-name confirmation and preserved external meta-audit. No delete-all shortcut near everyday actions.
