# Security specification / threat model

Assets: clinical and identity records, financial ledger, credential hashes, backup keys, local attachments, audit evidence. Attackers: ordinary app user, malicious renderer/input/file/backup, another Windows account, accidental operator, filesystem failure. A local Windows administrator, same-account debugger or stolen unlocked account can inspect process memory: offline software cannot absolutely protect secrets or enforce RBAC against that actor. Deploy separate protected Windows account/ACLs, full disk encryption, screen lock and physical access controls. This limitation is disclosed, not hidden by UI-only permission checks.

## Authentication / session
Argon2id v1.3 with random 128-bit salt, initial cost 64MiB/3 iterations/1 lane; benchmark on minimum hardware, never reduce without review. Password length 12–128 Unicode scalar values with >=12 non-whitespace characters, no hardcoded initial credentials. Normalize usernames (ASCII allowlist 3–64); do not normalize passwords. Confirm exact match during setup. Constant-time library verification, dummy verification for nonexistent users, persistent bounded backoff on failed logins. Error does not identify account existence. Avoid user-controlled unbounded Argon2 parameters. Password changes and privilege changes invalidate sessions.

Opaque 256-bit session IDs generated native; renderer holds only memory (never localStorage/sessionStorage). Native idle timeout 5/10/15/30 minutes; Never only explicit owner policy. Absolute session maximum 12h. Time authority monotonic in process; wall-clock rollback does not extend live sessions. Manual lock revokes capability immediately. Frontend heartbeat cannot unlock; only verified credentials establish new session. On OS lock/suspend, revoke session. Sensitive DOM unmounted on lock; dirty values held only in guarded renderer memory, cleared at logout, not plaintext disk storage. Reauthentication resumes or discards drafts.

## Authorization / persistence isolation
See PERMISSIONS.md. No raw SQL/FS IPC. Narrow Tauri capabilities, CSP default self, no remote content, eval, scripts or navigation; no HTTP client plugin; dev preview never pretends to be the desktop backend. SQL bound parameters and sort allowlists. Windows file ACLs limit installation data to intended account. Release database encrypted with SQLCipher or equivalent reviewed encryption; key protected using Windows DPAPI, never shipped in renderer, backup or source. Attachments use corresponding per-install authenticated encryption at rest with unique nonces. Encryption implementation/key recovery requires dedicated tests; plain SQLite engineering builds do NOT satisfy production privacy gate. Full-data backups require explicit privileged permission. Clinical data never appears in telemetry or debug logs.

## Activation
Single isolated native verifier stores ONLY a derived Argon2id PHC representation of the supplied mandatory fixed secret; never plaintext code, test fixture copy, obvious secret constant, log or frontend comparison. Receipt generated only after successful verification, bound to installation identity and Windows DPAPI CurrentUser plus machine identity where available, stored outside clinical backups. Atomic durable publication, retry limiting, reinstall preserves receipt. An entirely offline fixed secret is discoverable by a motivated reverse engineer; resistance to casual string searching is not cryptographic licensing. Local reset must not destroy clinic records. Positive verifier test injects the real input from an ephemeral private local test environment, never embeds it in tests/CI YAML.

## Files / output / diagnostics
Content sniffing, file limit, generated names, canonicalized managed roots, no traversal/reparse escapes; archive protections in recovery spec. Escape UI/print HTML; never dangerouslySetInnerHTML for notes. CSV formula-neutralization; filenames stripped of unsafe control characters. Open external documents only via scoped native path and confirmation. Local log rotation 5 files × 2MiB, retention 30 days, event IDs/codes/timing only, no passwords/code/session tokens/PHI/financial payload. User support export requires explicit review/redaction. Error correlations match redacted logs, not raw SQL in dialogs.

## Audit / destructive controls
Append-only SQL triggers deny normal audit UPDATE/DELETE; transaction-matched audit entries, redacted field-name change summaries, protected audit read grants. Hash chain provides tamper evidence, NOT protection from a privileged attacker who can rewrite both DB and chain. External checkpoint digest protected by OS key improves detection. Authentication failures persist events but no supplied password or unknown username. Role change old/new grants recorded. Patient archive ordinary path; destructive confirmations include exact subject/counts/consequences and typed identity. Backup/restore/data reset reauthentication + mandatory pre-backup. Business-layer confirmation token expires and binds exact operation/record set to prevent stale counts.

## Release security evidence
Cargo/npm advisory audits at pinned lockfiles; secret scan working tree/history; local data ACL/key tests; CSP/IPC review; hostile backup/files; all RBAC secondary surfaces; timing/backoff/clock/lock tests; tampered migrations; SQL injection; overflows; Unicode; full financial allocation concurrency/idempotency. No unresolved critical/high findings without a documented non-applicable justification approved by owner. No PHI in screenshots/fixtures. No online activation, analytics, paid APIs or undisclosed network calls.
